# AeternaLoop-Trinity v2.1.2 Candidate Notes

## Theme

v2.1.2 is a tuning phase.

The aim is to loosen over-strong memory, over-strong fusion, and over-diffuse trace fields before adding v2.2 features.

## Safety baseline already checked

The current tuning scripts assume the v2.1.2 safety pass is present:

- EWMA velocity blend no longer divides the velocity pull by `DT`.
- A/B relation docs use `R_AB_orderDifferenceRatio` as the primary name and keep `R_AB_relative` as a compatibility alias only.
- Energy wording separates `fieldEnergyProxy` from pheromone memory-style `pheromoneEnergyL2`.
- Surrogate/headless scans are recorded separately from future real `64^3` validation.

## Baseline candidate

`GAMMA = 0.005` is used as the current baseline candidate for these scans.

This is not an ideal-value claim. It means only that the v2.1.1 experiment family found relatively smaller energy growth while amplitude stayed near VEV.

## Coupling Mechanism Audit Plan

Experiment 017 showed that increasing effectiveMemoryCoupling moved A/B farther apart.

Hypothesis:
The current memory coupling may act like an absolute memory injection rather than an attractor. Depending on phase and memory state, this may push A/B apart.

Experimental correction:
- Add `MEMORY_COUPLING_FORMULA = "difference-attractor"`
- Use `fieldA += G * (fieldB.memory - fieldA.phi)`
- Use `fieldB += G * (fieldA.memory - fieldB.phi)`
- Use bidirectional snapshots to avoid update-order bias
- Test coupling before memory update

Primary check:
Does fieldABDistance decrease from start to end?

Secondary check:
Does fieldABDistance enter 0.01–0.1 without identity collapse?
