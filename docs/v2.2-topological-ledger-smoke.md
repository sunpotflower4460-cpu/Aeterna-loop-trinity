# v2.2 Topological Ledger Smoke

## Purpose

The Topological Ledger is an Observer-layer smoke test added before G8. It converts integer XY plaquette winding per z-slice into a reusable accounting tool for Trinity fields.

It exists after Observer V2 because Observer V2 improved distances and x-line winding reliability, but did not add local plaquette vortex accounting. This smoke is a G6-adjacent observer and a G8 preparation step.

## Scope

This PR adds metrics, smoke artifacts, validation, and documentation only. It does not modify runtime physics, implement G8, alter historical v2.1.2 artifacts, or reinterpret Observer V2 artifacts.

The 3D adaptation is intentionally narrow: XY plaquette ledger per z-slice. It does not implement full 3D vortex-core topology, YZ ledgers, or ZX ledgers.

## Periodic-boundary applicability

The ledger context records `boundaryCondition: "periodic"`, `periodicAxes: ["x", "y", "z"]`, `orientation: "xy"`, `supportedOrientations: ["xy"]`, and `sliceAxis: "z"`.

Strict integer gates apply only because the XY plaquette ledger is computed on periodic x/y slices. If a future runtime introduces non-periodic boundaries, the strict `totalWinding == 0` gate must not be reused without revision.

## Edge sharing / telescoping policy

The implementation computes shared periodic x-edge and y-edge phase differences once per z-slice and reuses those edges with opposite signs in adjacent plaquettes. This preserves the discrete telescoping discipline needed by the strict synthetic periodic checks.

## Phase wrapping convention

Phase deltas use principal-value wrapping into `(-π, π]`. Plaquette winding is `round(sumWrappedEdgeDeltas / 2π)`. The maximum closed-plaquette float residual is recorded as a floating-point sanity value, not as the main phenomenon metric.

## Valid and invalid plaquettes

A plaquette is invalid if any of its four corner amplitudes are below `validityAmpThreshold`, which defaults to `0.1`. Near-π edge ambiguity is recorded with `nearPiMargin: 0.3`.

Strict integer gates apply only to valid synthetic periodic cases. Runtime/noisy cases require reliability context. The current field initializer floors amplitudes around `0.05`, so low-amplitude cores can matter even when exact zero amplitudes are absent.

## Relationship to `computeVortexCount`

`computeVortexCount` counts vortex-like plaquettes on the center z-slice only, using an `abs(winding) > π` threshold. The Topological Ledger generalizes that into all z-slices, integer plaquette maps, positive/negative counts, net winding, invalid plaquette accounting, and global phase shift invariance checks.

The smoke includes a clean all-valid compatibility check requiring the center-slice ledger positive-plus-negative count to match `computeVortexCount` on the same field.

## Relationship to `computeWindingHistogram`

`computeWindingHistogram` measures x-axis global line winding across y,z lines. It is not the same quantity as local XY plaquette vortex winding.

The smoke uses a local `W=1` x-ramp fixture and local x-line histogram formula matching the finalized audit runner to verify that the x-line histogram can report dominant `W=1` while the XY plaquette ledger remains vortex-free.

## Synthetic test suite

The smoke records:

1. C-1 global phase shift invariance.
2. Seeded random periodic phase fields with strict per-slice and global zero net winding.
3. A branch-cut-safe known paired local plaquette fixture with equal positive and negative counts and net zero.
4. A low-amplitude invalid plaquette case.
5. Compatibility with `computeVortexCount` and distinction from x-line winding histograms.
6. A legacy U(1) equivariance regression for identical layout plus global phase offset.

## Runtime smoke

A limited runtime smoke attaches the ledger to a small runtime sample sequence. It records positive/negative counts, invalid plaquette counts, near-π edge counts, and `ledgerDelta` over time.

`ledgerDelta` is diagnostic only. It depends on time step, sample interval, and possible multiple events between samples; it is not a strict invariant.

## fieldA/fieldB identity policy

For the legacy U(1) equivariance regression, identical layout plus global phase offset must have identical plaquette maps because phase differences cancel the global offset.

This is not a universal G8 gate. In G8, fields may intentionally have different layouts, so fieldA/fieldB ledger mismatch is not automatically a failure. In coupling or fusion-style experiments, ledger agreement or disagreement may become an event detector rather than a proof claim.

## What this can and cannot claim

Topological Ledger is an Observer-layer accounting tool. It does not prove exact full 3D topology, biological life, consciousness, agency, or permanent survival.

Strict integer gates apply only to valid synthetic periodic cases. Runtime/noisy cases require reliability context.

## Relationship to G6 and G8

This smoke is G6-adjacent because it begins local plaquette topology accounting without claiming full 3D vortex-core topology. It prepares G8 by providing stricter observer bookkeeping for layout persistence, mismatch, and possible future fusion-event diagnostics.
