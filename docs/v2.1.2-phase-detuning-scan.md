# v2.1.2 Phase Detuning Scan

## Purpose

PR #27 corrected the observer. This scan maps a first lightweight g × Δω phase-locking / phase-drift boundary using legacy same-layout phase-offset initial conditions for clean phase dynamics.

## Corrected scan axis

Phase rotation advances by `omega * dt` per step. With `dt=0.03`, earlier tiny Δω values are expected to remain locked over 1000–2000 steps and are not suitable for boundary discovery. This scan therefore uses `OMEGA_B = 0.05, 0.11, 0.21, 0.41, 0.61` with `OMEGA_A=0.01`.

## Parameters

- Grid: 32^3
- Main scan steps: 2000
- Coupling-off calibration steps: 1000
- Sample interval: 50
- COUPLING_G: 0.003, 0.005, 0.0075
- PHEROMONE_ENABLED=false for clean phase dynamics
- Drift classification for this scan is expanded: phase_drift if thetaTotalTravel >= pi OR abs(driftRatePerStep) > 1e-4 rad/step in the second half.
- The drift-rate threshold is a v2.1.2 scan heuristic calibrated for `dt=0.03`, approximately 2000-step runs, and current sample intervals; it is not a universal physical constant.
- Future outputs should separate `structuralRegimeVerdict` from `phaseDynamicsVerdict` / `phaseBehavior`.
- `finalRegimeVerdict`, when present in future outputs, is only a legacy compatibility alias for `structuralRegimeVerdict`; do not use it for phase-dynamics interpretation.

## Adler / Arnold tongue interpretation

The qualitative comparison is `dθ/dt ≈ Δω - K_eff sin(θ)`: coupling-dominated rows are interpreted as phase-locking, detuning-dominated rows as phase-drift, and row transitions as `arnold_tongue_region_candidate` / `phase_boundary_candidate` only. This is a qualitative Adler-like comparison, not a confirmed Arnold tongue, and no exact `K_eff` is claimed.

## Phase rotation and verdict hygiene

Phase rotation currently rotates `phiRe` / `phiIm` and, for `PHASE_ROTATION_TARGET=field-and-memory`, memory fields; it does not rotate `velRe` / `velIm`. Because `real-runtime-v0` is second-order, this is an operational phase-drive approximation rather than an exact Adler model fit.

Use `phaseDynamicsVerdict` / `phaseBehavior` for phase-dynamics interpretation in future outputs. `structuralRegimeVerdict` is the PR #27 integrated classifier output from `classifyPhaseStructureRegime`; because that classifier has priority rules, it may include phase-like labels such as `phase-locking` or `phase-drift`.

## Limitations and next steps

- Legacy same-layout setup isolates phase dynamics but does not test structurally distinct fields.
- Boundary candidates need denser Δω rows and longer runs before confirmation.
- No v2.2 mechanisms or new physical terms were enabled.

Machine-readable outputs were written to `experiments/v2.1.2-phase-detuning-scan-results.json` and `experiments/v2.1.2-phase-detuning-scan-summary.json`.
