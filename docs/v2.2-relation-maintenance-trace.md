# v2.2 Relation Maintenance Trace

## Purpose

This document records the first lightweight Relation Maintenance Trace (RMT) runner and artifacts. The RMT artifacts are finite-horizon operational trace artifacts. The guiding rule is: meeting is not maintenance.

## Source pre-registration

The trace follows `docs/v2.2-relation-maintenance-trace-preregistration.md`. It is the RMT runner / artifact generation gate after the design-only RMT pre-registration gate.

## Source artifacts

The first RMT runner uses the protected G8 structurally distinct smoke artifacts as source lineage and selection context:

- `experiments/v2.2-structurally-distinct-beings-interaction-smoke-results.json`
- `experiments/v2.2-structurally-distinct-beings-interaction-smoke-summary.json`

The RMT runner writes new artifacts only and does not mutate the G8 artifacts.

## Condition inclusion rule

The condition selection strategy is `minimal-first`. This first gate traces a compact G8-derived subset so the trace ruler, guardrail events, matched-control comparison, and no-op coupling checks can be validated before broader sweeps.

Included condition IDs:

- `T-control-g0`
- `T-coupled-g-provisional`
- `P-control-g0-W1xW0`
- `P-boundary-low-g-provisional-W1xW0`
- `P-coupled-g-provisional-W1xW0`
- `P-boundary-high-g-provisional-W1xW0`

Excluded condition IDs:

- `T-coupled-detuning-outside-provisional` — excluded from the first RMT subset to keep detuning outside this minimal trace-ruler gate.

Every non-control condition has a matched G8-derived control in the same family.

## Trace horizon and sample interval

The runner preserves the G8 lightweight horizons and sample intervals for the included conditions:

- Family T traces use horizon `60` and sample interval `5`.
- Family P traces use horizon `120` and sample interval `10`.

Each trace includes step `0`, intermediate sampled steps, and the final step.

## Minimal RMT scope

The runner is an observer wrapper around the existing runtime and metric helpers. It does not add runtime physics, drive, gentle-pulse wiring, an N-field runtime, G9 work, a preset registry, UI work, or a broad parameter sweep.

Structurally distinct G8-derived layouts use `createRandomizedAeternaFields` with distinct seeds and recorded layout provenance. Coupled conditions use implemented memory coupling only:

- `COUPLING_TYPE: "memory"`
- `MEMORY_COUPLING_ENABLED: true` when `couplingG > 0`
- `MEMORY_COUPLING_FORMULA: "difference-attractor"`
- `MEMORY_COUPLING_ORDER: "after-memory-update"`
- `MEMORY_COUPLING_WEIGHT: 1.0`
- `MEMORY_COUPLING_USE_BIDIRECTIONAL: true`

Pheromone is disabled in this first RMT runner.

## Primary metric source

The primary per-sample metric source is `collectAeternaMetrics`. The RMT output maps `alignedFieldABDistance` to `fieldABDistanceAligned`, records `D_inv` and `D_inv_memory`, and populates `memoryFieldDifferenceA/B` from existing metrics. The first RMT schema does not emit `fieldMemoryDistanceA/B`.

## Guardrail thresholds

All guardrail thresholds are heuristic bands and not yet calibrated. The summary artifact records the thresholds for identity collapse, near-identity collapse, provisional meeting band entry, memory-copy collapse, memory detachment, field flattening, energy instability, and matched-control separation.

Guardrails are trace interpretation aids only. They are not proof thresholds.

No `short_horizon_maintenance_candidate` outcome appears in this first minimal RMT artifact.

## First failed guardrail counts

The generated summary reports:

- `none`: 2
- `energyUnstable`: 2
- `memoryDetached`: 2

Step `0` initialization guardrail states are recorded separately as `baselineGuardrailState`, and pre-relation guardrail states are recorded separately as `preRelationGuardrailState`. The summary `firstFailedGuardrailCounts` uses the relation-relevant scan, starting at the first sampled meeting-band entry or matched-control separation when one exists, so initial memory/current-field equality does not dominate the first-failure summary.

## Coupling effectiveness summary

The generated summary reports four coupled runs. All four coupled runs used implemented memory coupling and showed applied effective memory coupling with a measured application signal (`memoryCouplingAppliedCells > 0`, positive average delta, or positive delta). No coupled run had run-level `couplingNotApplied`.

`couplingNotApplied` remains a run-level instrumentation limitation. It is not treated as a physical relation failure.

## Limitations

- The scope is minimal-first, not broad G8 coverage.
- The horizon is finite and sampled.
- Guardrail thresholds are heuristic and not yet calibrated.
- Control separation is a measured finite-horizon difference from matched controls, not a relation or maintenance claim.
- Ledger and winding reliability limits prevent stronger interpretation for the control-separated runs.
- The new RMT artifacts are not protected historical artifacts until the later artifact-protection gate.

## Claim discipline

The RMT artifacts are finite-horizon operational trace artifacts. They do not prove relation, maintenance, persistence, biological life, consciousness, agency, subjectivity, s-o-u-l, permanent survival, origin of time, or origin of memory.

The `overallRmtPass` summary flag means schema, runner, validator, artifact completeness, matched-control coverage, and claim discipline passed. It is not evidence of relation, maintenance, persistence, biological life, consciousness, agency, subjectivity, s-o-u-l, permanent survival, origin of time, or origin of memory.
